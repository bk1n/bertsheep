Verdict

The runner does what its docstrings promise. It preprocesses once and builds one distance matrix, runs a resumable tuning stage, then works through a resumable grid in which every arm of a cell is scored on the same rows. Nothing on the happy path crashes. The problems are about what the numbers will mean. Seed 0 is tuned on and then reported as a replicate. Only the fine-tuned arm gets a hyperparameter search. And neither the tuning store nor the results file is keyed on the configuration that produced it. Each of these is a few lines to fix, and all of them are cheaper before the first real run than after.

Fix before the first real run

  • H1Tune on a seed outside 0–29, or drop seed 0 from the analysis. The fine-tuned seed-0 cell is otherwise a re-run of the winning Optuna trial.
  • H2Decide how the pretrained arm and the XGBoost baseline get tuned, or state the asymmetry. Right now only the fine-tuned arm is searched.
  • M1Key the tuning study and the results resume on mutation and min_cluster_size (M1, M2). Both currently resume silently across configurations.
  • M4Fix reinit_n before tuning if Question 2 is to compare pre-trained and fine-tuned layers.

Run order

Counted in model fits and grid cells, not time. Tuning runs to completion for both distributions before any grid cell starts. The grid then runs all 30 in-distribution seeds before the first out-of-distribution one, because product(distributions, seeds) puts distribution in the outer loop.

tune · out75 trials
grid · incells 1–90
grid · outcells 91–180
done (1) missing seed 0: the split Optuna tunes on seed 0 finetuned: keeps every epoch (GIF)

Within a block, cells run down each seed column (baseline → pretrained → finetuned), then move one seed to the right. Hover a cell for its position in the queue.

Model.__init__, in order

  • _seed(seed) seeds Python, NumPy and torch (CPU and CUDA) and returns the generator the train loader shuffles with. This happens before the network exists, so the head's initialisation is seeded too.
  • _create_model_dir() creates out/models/EGFR-butina-{in|out}-{frozen|finetuned}-YYYY-mm-dd-HHMMSS/checkpoints/ with exist_ok=True (L3).
  • Tokeniser plus RobertaForSequenceClassification(num_labels=1, hidden_dropout_prob=dropout), moved to CUDA if available. Then _reinit_layers(reinit_n) if above 0. With freeze, roberta.requires_grad_(False).
  • _save_run_record() writes config.json and splits.parquet (row, split) from splitter.split(). split_frames() reads them back with iloc.
  • _init_head_bias() sets the head bias to the train-label mean. Then three pre-tokenised DataLoaders (max 128 tokens, only train shuffled), AdamW over LLRD groups (head, layers 3→1, embeddings, each split into decayed and undecayed), and a linear warmup/decay schedule over len(train_loader) × 80 steps.

Issues

Ranked by how much each one could change a conclusion drawn from the results. “Probe” means a scratch test in the scratchpad asserted the current behaviour and passed, so the behaviour is confirmed rather than inferred. No repository code was changed.

High

These affect what Question 1 can conclude

H1

Seed 0 is both the tuning run and a reported replicate

experiment.py:27, :31, :287 · tuning.py:18
What happens
Optuna picks the parameters with the lowest test loss on seed 0's split, and every trial uses model seed 0. The grid then builds the fine-tuned cell for (in or out, seed 0) with the same split, the same model seed and those parameters. It re-runs the winning trial, identical up to GPU nondeterminism. That cell's test loss is the best of 75 attempts by construction, and its valid score is probably optimistic too. No other arm or seed gets this treatment, and the GIF trajectory comes from the same cell.
Evidence
TUNING_SEED == TUNER_SEED == GIF_SEED == 0 and 0 in range(N_REPEATS). Probe test_seed_zero_is_tuning_split_tuner_model_seed_and_a_reported_replicate passes.
Fix
Tune on a seed outside the reported range, e.g. TUNING_SEED = N_REPEATS, or leave seed 0 out of the Q1 analysis. GIF_SEED can stay 0.
H2

Only the fine-tuned arm is tuned

experiment.py:38–45, :201–203 · tuning.py:164–167
What happens
Question 1 asks whether fine-tuning beats the frozen encoder and the fingerprint baseline. The fine-tuned arm gets a 75-trial search. The pretrained arm borrows those parameters, which were sized for moving the whole encoder. XGBoost runs one fixed configuration. Some of any gap in fine-tuning's favour will be a gap in tuning effort.
Evidence
The code path above. todo.md already flags the pretrained LR (a 2-epoch smoke run at 6.9e-5 finished near R² 0). The baseline half isn't logged anywhere.
Fix
Give the pretrained arm its own small study. Its encoder is frozen and in eval mode, so its features are fixed and could be computed once, which would make head-only trials cheap. Give XGBoost a short search too, or state the asymmetry in the write-up.
Medium

Silent-reuse and methodology risks

M1

Tuned parameters aren't tied to the frame they were tuned on

tuning.py:97, :204–213 · experiment.py:147–148
What happens
The study and its JSON are named {target}-{method}-{distribution}, which leaves out mutation, min_cluster_size, the label and the preprocessing. Say --mutation L858R is run after a wild-type run. load_if_exists=True resumes the finished wild-type study with 0 trials remaining and rewrites the same JSON, and the mutant grid is then fitted with wild-type parameters. The results file is keyed by mutation, so nothing in it shows the mismatch.
Evidence
Probe test_study_name_ignores_mutation_and_min_cluster_size passes. The issue is latent for now because out/tuning/ doesn't exist yet.
Fix
Put mutation and min_cluster_size in the study name, or write the frame's size plus a hash of its SMILES into the JSON and check it in _params.
M2

Resume counts any existing row as done, whatever produced it

experiment.py:20, :272–283, :307–309
What happens
_done() keys on (arm, distribution, seed) only. After a change to MIN_CLUSTER_SIZE, XGB_PARAMS, the tuned parameters, the epoch budget or the code, old rows still count as finished and new rows are appended to the same file. Smoke-run rows count by design. The existing (baseline, in, 0) row will be kept whatever changes before the real run.
Evidence
Probe test_done_ignores_min_cluster_size: an Experiment built with min_cluster_size=5 ran nothing and returned the row from min_cluster_size=1.
Fix
Add min_cluster_size (and a hash of the config) to KEY or to the results filename, or check that existing rows match the current config before skipping them.
M3

A “smoke run” runs the full tuning first

experiment.py:369–371 · CLAUDE.md commands
What happens
Any transformer arm triggers tune() for every selected distribution, and optimise() runs each study up to 75 trials. The smoke example in CLAUDE.md, uv run bertsheep EGFR --arms pretrained --seeds 3, therefore runs 150 fine-tuning fits before its first pretrained cell. No flag caps the trials or skips tuning.
Fix
Add a --trials flag passed to Tuner(n_trials=…), or a --no-tune flag that fails fast when the JSON is missing.
M4

reinit_n can change what Question 2's “pre-trained” reference means

tuning.py:49 · model.py:295–296, :764–765
What happens
If the search picks reinit_n = 1, every fine-tuned run starts with a randomly re-initialised top encoder layer, and init.pt (the RSA reference) stores those random weights. Top-layer RSA would then measure random → trained rather than pre-trained → fine-tuned. The frozen arm drops reinit_n, so the two arms would also differ by more than freezing.
Fix
Pin reinit_n = 0, or compare against the published weights in Q2. Decide before the studies run, because the choice changes the search space.
M5

In and out are differently sized experiments

splitters.py:338–347
What happens
In-distribution rounds 0.70 and 0.15 to 3 folds, then 2, giving 5,868 / 1,467 / 1,467 on every seed. Out-of-distribution trains on 5,200–6,991 molecules and validates on 708–2,250, and its valid label mean ranges from −5.52 to −3.53. So an in–out gap mixes distribution shift with training-set size and valid-set composition, and R² on a small or shifted valid set is noisy.
Evidence
Measured on the real frame. See Splits in practice.
Fix
Keep n_train and n_valid in the analysis (both are already recorded), report RMSE next to R², and consider an out split that balances molecules rather than clusters.
M6

The trial count includes failed and orphaned trials

tuning.py:214
What happens
75 − len(study.trials) counts trials in the FAIL and RUNNING states. A process killed mid-trial leaves a RUNNING trial that counts forever, and a CUDA OOM counts as a trial. On restart, TPESampler(seed=0) resets its random state, so a resume inside the first 10 random trials re-proposes configurations that were already tried.
Fix
Count only COMPLETE and PRUNED trials, and mark stale RUNNING trials as failed on start.
Low

Robustness, record-keeping and ergonomics

L1

The tuning objective includes the untrained epoch

tuning.py:168
What happens
history["test_loss"].min() includes epoch −1, the untrained model predicting the training mean, which fit() never selects. A trial that never beats the mean predictor scores as if it matched it. So does a trial that diverges to NaN, because min() skips NaN. The winner is unlikely to change, but TPE gets a flattering picture of bad regions of the search space.
Evidence
Probe test_objective_min_includes_untrained_epoch: the objective returns 0.5 while the selected epoch's loss is 2.0.
Fix
Take the minimum over epochs ≥ 0, i.e. the best_epoch row.
L2

A NaN fit stops the whole grid

model.py:772–786, :641, :804
What happens
If test loss is NaN on every epoch, best_epoch and best_state stay None. In the fine-tuned arm, fit() then raises a bare StopIteration from _save_checkpoint. In the pretrained arm, evaluate() fails in load_state_dict(None). Cells have no error handling, so one diverged fit stops the run, though resuming works.
Evidence
Probes test_nan_fit_crashes_when_checkpointing and test_nan_fit_crashes_evaluate_without_checkpointing.
L3

Run directories are named to the second, with no seed

model.py:337–342
What happens
Two Models built in the same second share a directory (exist_ok=True) and overwrite each other's config.json and splits.parquet. That's unlikely here, since every fit takes longer than a second. The bigger practical problem is that the 150 tuning trials and the 60 fine-tuned grid runs follow the same name pattern with no seed or trial number. Only the results CSV's run_dir column tells them apart.
Evidence
Probe test_two_models_in_the_same_second_share_a_run_dir.

ChemBERTa isn't pinned to a revision

Checked and sound

Things I suspected and then ruled out, or confirmed working as intended.

  • ok All three arms of a cell see identical rows. One Splitters per (distribution, seed), and split() is deterministic because it uses an integer random_state. Tested by test_arms_are_scored_on_the_same_split.
  • ok Rebuilding Butina clusters for every seed is cheap. It takes 0.13 s on the real frame, because the distance matrix is shared rather than recomputed.
  • ok Valid never drives a choice. XGBoost early-stops on test, Model selects epochs on test, and Optuna scores test. Valid is scored every epoch only for the R² curve in history.csv. It is printed, but no code reads it back.
  • ok XGBoost predicts from the best round. After early stopping, predict() uses best_iteration. The existing row stopped at round 1,105 of 2,000.
  • ok The frozen arm really is frozen. The encoder has requires_grad=False and is put back in eval mode each epoch, so dropout is off. AdamW skips parameters with no gradient, so there is no weight-decay drift. Tested by test_frozen_epoch_trains_the_head_only.
  • ok Seeding comes before the head exists. The train loader shuffles with its own seeded generator, and the test and valid loaders don't shuffle.
  • ok No leakage through indices or the head bias. Splits are positional and applied with iloc, and the head bias is the train label mean only.
  • ok Resume works. Rows are appended as each cell finishes, and np.int64 seeds read from the CSV hash the same as Python ints. Tested by test_grid_resumes_rather_than_repeating.
  • ok The checkpoint budget matches todo.md. Each of the 60 fine-tuned runs writes init.pt and best.pt. Only the two seed-0 fine-tuned runs keep every epoch.

Doc drift

Found while tracing. These are in CLAUDE.md and todo.md, not the README, and each is stale against the code as of 1b17cf7.

  • CLAUDE.md lists the pipeline as _load → _filter → _deduplicate → _canonicalise → _transform_labels. The real order is _load_cached → _filter → _extract_mutations → _select_mutation → _canonicalise → _drop_acyclic → _deduplicate → _transform_labels.
  • CLAUDE.md calls chemistry.py an empty placeholder. It holds the full Chemist class.
  • CLAUDE.md says torch, transformers and umap-learn are not in pyproject.toml. They are, along with optuna and xgboost.
  • CLAUDE.md says Eda writes to figures/<target>_<name>.png. FIGURE_DIR is out/eda.
  • CLAUDE.md says the README describes five kinase targets, Ki, an XGBoost baseline and nested CV, and that almost none of it is built. The README now describes EGFR only, doesn't mention Ki or XGBoost, and most of its Question 1 is built.
  • todo.md leaves “Optuna (TPESampler) hyperparameter search, once per seed” open, but the README and the code both tune once, on the first seed.

How this was made

  • Read every module on the run path (experiment, data, chemistry, splitters, tuning, model), the four test files, README.md, todo.md and the existing out/ contents.
  • Coverage: COVERAGE_CORE=ctrace uv run --no-sync --with pytest-cov pytest --cov=bertsheep --cov-branch --cov-context=test. Data files, the JSON report and pytest's temp dirs went to the session scratchpad, and the cache provider was disabled.
  • Split measurements: a scratch script ran Data._preprocess() from the existing parquet cache, built the distance matrix, then called Splitters.split() for seeds 0–29 in both distributions. It wrote nothing inside the repo.
  • Probes: 9 scratch tests with MODEL_DIR, EXPERIMENT_DIR and TUNING_DIR monkeypatched to temp dirs.
  • No code was changed. git status shows only the todo.md edit that was already there, plus this file.
